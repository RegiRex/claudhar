**Sixth Claudhar alpha: no more freezes leaving a game, and Dark Moon's vertex pipelines
first.** A test build, not a finished emulator.

### What changed

- **Leaving a game no longer freezes the app.** The "crashes" leaving Dark Moon in 0.0.5
  were Android's "not responding": Claudhar waited for every queued shader build while
  holding a lock the screen needs, and Dark Moon on Qualcomm's driver had dozens queued,
  several seconds each. Queued builds are now dropped when you leave (they are rebuilt at
  the next start), and the ones already running finish without holding that lock.
- **Dark Moon's GPU vertex pipelines are built first.** Until a draw's GPU vertex pipeline
  is ready, its vertices are shaded on the CPU, which in 0.0.5 took 7–8 s of every 10 s in
  Dark Moon on Qualcomm's driver (9–17% speed). Those pipelines are now built before the
  other kind, with twice the threads, and the emulation thread no longer asks the driver
  cache twice for the same pipeline. This should shorten the slow start, not remove it.
- **Quick shader builds is removed.** It did not help on either driver: quick builds took
  longer than normal ones (Turnip 32–35 ms against 27–28 ms, Qualcomm 2.7–10 s against
  0.9–5 s) and ubershader draws did not fall.
- **Testing section:** besides the GPU driver, resolution and Prepare graphics before
  starting, it now has two Azahar settings that change the size of the shaders the driver
  compiles: Accurate multiplication (off makes vertex shaders smaller, but can bring back
  graphical bugs it fixes) and Disable SPIR-V optimizer (off spends more time in Claudhar
  to hand the driver smaller shaders).
- **Crash reports** now end with the crashed session's log; in 0.0.5 they showed the next
  launch's.
- Everything in [0.0.5-alpha](https://github.com/RegiRex/claudhar/releases/tag/0.0.5-alpha).
  Details: [Phase 1](https://github.com/RegiRex/claudhar/blob/0.0.6-alpha/docs/PHASE1_UBERSHADER.md#exit-build-order-and-lookups-006-alpha).

### Install

Download `claudhar-0.0.6-alpha-arm64.apk` below and install it over 0.0.5-alpha. Settings
carry over; the Quick shader builds setting simply disappears.

### What to test

- **Dark Moon from a deleted shader cache on Qualcomm's driver**, as before. In the
  `Claudhar shading:` lines, `building: ... GPU-vertex ubershader` should fall much faster
  than 2–5 per 10 seconds, and `CPU-vertex fallbacks` and `CPU vertex shading of
  fallbacks` should drop sooner. Then leave the game: it should return to the game list
  within a few seconds without "not responding".
- **Dark Moon on Turnip** (Per-Application Settings, Testing, GPU driver), same test.
  Turnip built Sonic's pipelines in about 30 ms; if it does the same for Dark Moon, the slow
  start may disappear.
- **Accurate multiplication off** for Dark Moon, same test, watching both the speed and the
  graphics.
- **Prepare graphics before starting** after playing a game once and then switching its
  driver: the loading screen should show Building Pipelines with a count.

### Known limits

- Not yet run on a device.
- Dark Moon's first minutes on Qualcomm's driver are expected to stay slow, only less so;
  the next steps for that are in the Phase 1 notes.
- The limits of 0.0.3-alpha still apply.
