**Fifth Claudhar alpha: a Testing section and two graphics test settings.** A test build,
not a finished emulator.

### What changed

- **Testing section** at the top of the settings, both the global ones and each game's
  Per-Application Settings. It gathers the settings under test: the game's GPU driver (per
  game), the internal resolution, and the two new settings below. They are ordinary
  settings: a game's choice there overrides the global one, is marked as customized, and a
  long press returns it to the global value. The driver and the two new settings apply when
  the game next starts.
- **A driver cache per driver.** A game's compiled pipelines were kept in one file per
  game, and the next driver to run that game threw it away. Each driver now keeps its own,
  for the four drivers a game used most recently, so switching a game between drivers to
  compare them no longer recompiles everything each time. Existing caches are kept for the
  driver that made them.
- **Prepare graphics before starting** (off by default). After a driver change or an
  update, the graphics the game recorded in earlier sessions are built at the loading
  screen, on all cores and with a progress count, so play starts with them ready instead of
  drawing with the slower ubershader while they build. It changes nothing during play.
- **Quick shader builds** (off by default, a test). Each new shader is built without the
  driver's optimizations first, so it replaces the slower ubershader sooner, and then built
  optimized on separate low-priority threads. Whether that helps depends on the driver: one
  that is not much faster without optimizations only gets extra work in the background. The
  log shows both build times, so a test can tell.
- Everything in [0.0.4-alpha](https://github.com/RegiRex/claudhar/releases/tag/0.0.4-alpha),
  including the GPU driver per game. Details:
  [Phase 1](https://github.com/RegiRex/claudhar/blob/0.0.5-alpha/docs/PHASE1_UBERSHADER.md#driver-caches-preparing-before-play-and-quick-builds-005-alpha).

### Install

Download `claudhar-0.0.5-alpha-arm64.apk` below and install it over 0.0.4-alpha. Settings
carry over.

### What to test

- **Switching a game's driver.** Play a game with one driver, then with another, then the
  first again. The second time with each driver, the early `Claudhar shading:` lines should
  show few ubershader draws and little `building: specialized`.
- **Prepare graphics before starting.** Switch a game's driver, turn the setting on and
  start the game. The loading screen shows Building Pipelines with a count, and the log
  says `Claudhar: built N pipelines before starting in T ms`. Compare the first minute's
  speed with the setting off.
- **Quick shader builds.** With the game's shader cache deleted, play the same stretch with
  it on and then off. With it on, the shading line ends with `quick builds N (X ms each),
  optimized after them M (Y ms each)`. It helps if X is well below Y and the ubershader draw
  counts fall; if not, the setting will be removed.

### Known limits

- Not yet run on a device.
- Moving a game between two drivers that support different features still regenerates its
  shaders at the loading screen; its compiled pipelines are kept.
- The limits of 0.0.3-alpha still apply.
